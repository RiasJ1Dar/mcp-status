# Інструкція: mcp-status

Покроково: збірка, запуск, авто-скан конфігів, ручний список для **Grok Bot**, індикатори, toast і автозапуск.

Короткий огляд продукту — у [README.md](README.md). English: [INSTRUCTIONS.md](INSTRUCTIONS.md).

---

## 1. Вимоги

- Windows 10/11 (трей, toast, автозапуск).
- [Rust](https://rustup.rs/) (`cargo` у PATH).
- Linux/macOS: лише `cargo test` / `mcp-status --once` (без трею).

---

## 2. Збірка

```powershell
git clone https://github.com/RiasJ1Dar/mcp-status.git
cd mcp-status
cargo build --release
```

Бінарник: `target\release\mcp-status.exe`.

Перевірка без трею:

```powershell
.\target\release\mcp-status.exe --once
```

---

## 3. Запуск на Windows

| Дія | Команда |
|---|---|
| Трей (постійно) | `.\target\release\mcp-status.exe` |
| Один знімок у консоль | `.\target\release\mcp-status.exe --once` |
| Увімкнути автозапуск | `.\target\release\mcp-status.exe --autostart-on` |
| Вимкнути автозапуск | `.\target\release\mcp-status.exe --autostart-off` |
| Статус автозапуску | `.\target\release\mcp-status.exe --autostart-status` |

Або задай змінну `MCP_STATUS_AUTOSTART=1` перед звичайним запуском — Run-ключ пропишеться сам.

Іконка з’явиться в системному треї. ПКМ / меню — список MCP з ● / ○ / ?.

---

## 4. Що означають індикатори

| Знак | Стан | Коли |
|---|---|---|
| ● | live | TCP до `url` успішний |
| ○ | dead | TCP до `url` не вдався; або agent-exchange недоступний |
| ? | unknown | stdio: процес не знайдено / неоднозначно; або запис без `url` і `command` |

Toast (Windows) приходить **лише коли стан змінився**. Перші ~15 с після старту — тиша (`MCP_STATUS_TOAST_SUPPRESS_SECS`).

---

## 5. Звідки береться список (авто)

Програма читає `mcpServers` з таких файлів (якщо існують):

| Джерело | Шлях (Windows) |
|---|---|
| Cursor | `%USERPROFILE%\.cursor\mcp.json` |
| Cursor (legacy) | `%APPDATA%\Cursor\User\globalStorage\cursor.mcp\settings.json` |
| Claude Code | `%USERPROFILE%\.claude.json`, `%USERPROFILE%\.claude\settings.json` |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` |
| Jan | `%APPDATA%\Jan\data\mcp_config.json` |
| AnythingLLM | `%APPDATA%\anythingllm-desktop\storage\plugins\anythingllm_mcp_servers.json` |

У `--once` внизу друкується `candidates:` — ✓ файл є, · немає.

**Не скануються:** проєктні `.cursor\mcp.json` (немає кореня воркспейсу).

---

## 6. Grok Bot і ручний список

Конектори Grok Bot (Gmail, Drive, Calendar, GitHub тощо) живуть у **хмарному** каталозі акаунта. У `%APPDATA%\Grok Bot` немає локального `mcpServers`, тому авто-скан їх не бачить.

### Крок за кроком

1. Скопіюй зразок:

```powershell
copy mcp-status.example.json $env:USERPROFILE\.mcp-status.json
```

2. Відредагуй `%USERPROFILE%\.mcp-status.json` у Блокноті / VS Code.

3. Формат:

```json
{
  "mcpServers": {
    "grok-github": {},
    "grok-gmail": {
      "url": "https://твій-endpoint-якщо-знаєш"
    }
  }
}
```

- Порожній об’єкт `{}` — запис у треї як **?** (просто «бачити в списку»).
- `"url": "https://..."` — пінг TCP → ● / ○.
- `"command": "шлях\\до.exe", "args": []` — stdio-евристика за іменем процесу.

4. Альтернативні шляхи до того самого файлу (перший знайдений з ручних — найвищий пріоритет):

| Пріоритет | Шлях |
|---|---|
| 1 | змінна `MCP_STATUS_CONFIG` = повний шлях до JSON |
| 2 | `%USERPROFILE%\.mcp-status.json` |
| 3 | `%APPDATA%\mcp-status\mcp-status.json` |

Ручний файл читається **раніше** за Cursor/Claude/Jan: те саме ім’я перекриває авто-скан.

5. Перевір:

```powershell
.\target\release\mcp-status.exe --once
```

Має з’явитись рядок на кшталт `? grok-github  (unknown transport)` і в `candidates:` — ✓ на `.mcp-status.json`.

## 7. Змінні середовища

| Змінна | За замовчуванням | Навіщо |
|---|---|---|
| `MCP_STATUS_INTERVAL_SECS` | `10` | Інтервал опитування в треї |
| `MCP_STATUS_TOAST_SUPPRESS_SECS` | `15` | Тиша toast після старту |
| `MCP_STATUS_EXCHANGE_URL` | `http://127.0.0.1:9750/` | agent-exchange; порожній рядок = вимкнути |
| `MCP_STATUS_CONFIG` | — | Шлях до ручного JSON |
| `MCP_STATUS_AUTOSTART` | — | Якщо задано — увімкнути Run при старті |
| `MCP_STATUS_TOAST_LOG` | — | На non-Windows друкувати «toast» у stderr |

Приклад PowerShell:

```powershell
$env:MCP_STATUS_INTERVAL_SECS = "30"
$env:MCP_STATUS_CONFIG = "D:\configs\my-mcp.json"
.\target\release\mcp-status.exe
```

## 8. Обмеження (коротко)

- Пінг `url` — лише TCP connect, не повний MCP handshake.
- stdio: колізії імен (`node`, `npx`, `python`); порівнюється basename команди.
- Grok cloud без ручного JSON у списку не з’явиться.
- UTF-8 **без BOM** для JSON бажаний; BOM зараз обробляється, але краще без нього.

---

## 9. Типові проблеми

| Симптом | Що зробити |
|---|---|
| `(no MCP servers found…)` | Немає жодного конфігу; створи `.mcp-status.json` або додай MCP у Claude/Cursor/Jan |
| Claude Desktop «порожній», хоча Claude Code має MCP | Норма: Desktop prefs ≠ `.claude.json`. Дивись Claude Code |
| `skip … expected value at line 1` | Файл з BOM / не JSON — збережи UTF-8 |
| Grok не видно | Додай імена в `.mcp-status.json` (розд. 6) |
| Toast немає | Перші 15 с глушаться; далі — лише на **зміну** стану |
